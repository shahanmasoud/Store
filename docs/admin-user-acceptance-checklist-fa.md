# چک‌لیست پذیرش کاربر پنل مدیریت

این سند مسیر واحد و عملی تست پنل مدیریت Store است. ترتیب سناریوها مطابق مسیر فعلی کاربر است: ورود و کاربران، کالا و انبار، مشتری، اعداد، چک، نسیه و سررسید، سپس بکاپ.

## روش استفاده

- ابتدا روی محیط آزمایشی یا داده آزمایشی اجرا کنید. کنار هر سناریو یکی از وضعیت‌های `قبول`، `رد` یا `اجرا نشد` را ثبت کنید.
- سناریو را یک‌بار در Chrome دسکتاپ و یک‌بار روی گوشی واقعی اجرا کنید. اگر گوشی در دسترس نیست، موقتاً نمای `390 × 844` را بررسی کنید و نتیجه را «شبیه‌سازی موبایل» بنویسید، نه «گوشی واقعی».
- در موبایل همیشه نبود اسکرول افقی و هم‌پوشانی، دیده‌شدن دکمه ذخیره با صفحه‌کلید باز، هدف لمسی مناسب و بازگشت درست با دکمه Back را کنترل کنید.
- برای مبالغ و مانده‌ها از مقدارهای آزمایشی قابل تشخیص استفاده کنید و پیش و پس از عملیات اسکرین‌شات بگیرید.
- سناریوهای دارای نشان **نیازمند تأیید production** را روی سایت اصلی اجرا نکنید مگر مالک فروشگاه همان عملیات را صریحاً تأیید کرده باشد.
- رمز، توکن، فایل `.env`، تصویر مدارک و دیتابیس را در گزارش ایراد، چت یا GitHub قرار ندهید.

2. پس از ورود، نام حساب و خانه مدیریت را بررسی و سپس خارج شوید.

**انتظار:** خطای ورود نامعتبر فارسی و بدون افشای جزئیات فنی است؛ ورود معتبر به خانه می‌رسد؛ خروج، صفحات مدیریت را دوباره محافظت می‌کند.

- دسکتاپ: فرم وسط صفحه، پیام‌ها خوانا و فوکوس صفحه‌کلید مشخص باشد.

### AUTH-02 — تغییر رمز **نیازمند تأیید production**

2. در محیط آزمایشی، رمز جدید معتبر و تکرار آن را ثبت کنید.
3. خارج شوید؛ رمز قبلی باید رد و رمز جدید پذیرفته شود. در پایان رمز آزمایشی را طبق سیاست تیم بازگردانید.

**انتظار:** اعتبارسنجی فارسی روشن است؛ نشست‌های قبلی بی‌اعتبار می‌شوند؛ هیچ رمز یا hash در صفحه یا پیام دیده نمی‌شود.

- دسکتاپ: نمایش/پنهان‌کردن رمز و پیام موفقیت را بررسی کنید.
- موبایل: dialog بریده نشود و دکمه ذخیره پشت صفحه‌کلید نماند.
- نتیجه: `قبول / رد / اجرا نشد` — توضیح:

### AUTH-03 — ساخت و ویرایش زیرمدیر **نیازمند تأیید production**

1. زیرمدیر آزمایشی با نام کاربری یکتا، رمز معتبر و فقط یک مجوز بسازید.
2. با آن حساب وارد شوید؛ فقط منوهای مجاز را باز کنید و یک مسیر غیرمجاز را مستقیم امتحان کنید.
3. با مدیر اصلی مجوز را تغییر دهید؛ نشست قبلی زیرمدیر باید باطل شود.
4. حساب آزمایشی را غیرفعال کنید و ورود دوباره را بیازمایید.

**انتظار:** منو و API هر دو دسترسی غیرمجاز را مسدود می‌کنند؛ حذف به‌صورت غیرفعال‌سازی است؛ مدیر اصلی و سوابق فعالیت حفظ می‌شوند.

- موبایل: فهرست به‌شکل کارت، dialog تمام‌صفحه و دکمه‌های بدون هم‌پوشانی باشد.

### DUE-02 — سررسید پرداخت نسیه فروش **ثبت مالی؛ نیازمند تأیید production**

1. فاکتور آزمایشی با دو پرداخت pending و دو موعد بسازید.
2. موعد زودتر را از موعد دوم عقب‌تر ببرید و سپس موعدها را جداگانه حذف کنید.

**انتظار:** موعد سند فروش همیشه با زودترین پرداخت pending همگام است؛ پس از حذف همه موعدها خالی می‌شود؛ پرداخت دریافت‌شده یا فاکتور لغوشده قابل ویرایش نیست.

- دسکتاپ: تاریخچه و برجسته‌شدن پرداخت مرتبط را ببینید.
- موبایل: فرم، پیام نسخه stale و CTAها بدون overflow باشند.

## دروازه عملیات خطرناک production

موارد زیر بخشی از تست عادی نیستند و هر بار تأیید صریح و جداگانه می‌خواهند:

| عملیات | حداقل پیش‌شرط |
|---|---|
| تغییر رمز واقعی مدیر | مالک آماده ثبت امن رمز جدید باشد؛ مسیر بازیابی ورود مشخص باشد. |
| ساخت/ویرایش/غیرفعال‌سازی کاربر واقعی | نام، نقش و مجوزها کتبی تأیید شوند. |
| ثبت خرید، اصلاح موجودی، چک، سند یا فروش نسیه واقعی | سند مرجع و مبلغ/تاریخ دوباره کنترل و مسئول ثبت مشخص شود. |
| ابطال چک یا غیرفعال‌سازی شخص | اثر روی عملیات آینده و حفظ تاریخچه بررسی شود. |
| migration، pull یا deploy | bundle تازه و verify‌شده از DB و media، برنامه بازگشت و پنجره نگهداری وجود داشته باشد. |
| restore یا جایگزینی داده production | وب‌اپ متوقف، بکاپ تازه از وضعیت فعلی، restore آزمایشی موفق و runbook بازبینی‌شده باشد. |

پس از هر عملیات تأییدشده، زمان، اجراکننده، شناسه رکورد و نتیجه ثبت شود؛ خود رمز، توکن یا اطلاعات محرمانه ثبت نشود.

## قالب ثبت ایراد

برای هر ایراد یک شناسه یکتا با قالب `UAT-YYYYMMDD-01` بسازید. نمونه: `UAT-20260914-01`.

```text

نسخه یا commit:
دستگاه و اندازه صفحه:
سیستم‌عامل و نسخه Chrome:
حساب/نقش: مدیر اصلی یا نام نقش زیرمدیر (بدون رمز)

پیش‌شرط:
مراحل تکرار:
1.
2.
3.

نتیجه فعلی:
نتیجه مورد انتظار:
تکرارپذیری: همیشه / گاهی / یک‌بار
شناسه رکورد آزمایشی: در صورت وجود
زمان دقیق رخداد:
```

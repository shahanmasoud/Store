# فاز ۳۹ — دسترس‌پذیری پنل مدیریت

## محدوده تحویل

دسترس‌پذیری مسیر اصلی پنل در Chrome واقعی، برای دسکتاپ `1440×900` و موبایل `390×844` بررسی شد:

- وجود یک landmark اصلی و عنوان سطح یک؛
- بازشدن منوی موبایل و دیالوگ تغییر رمز با صفحه‌کلید؛
- بازگشت فوکوس به کنترل آغازکننده پس از بستن؛
- حداقل هدف لمسی ۴۴ پیکسل برای دکمه منوی موبایل؛
- حذف حرکت غیرضروری در حالت `prefers-reduced-motion`؛
- اعلام معنایی حالت‌های loading، error و empty دسته‌بندی با `status` و `alert`.

آزمون موبایل نشان داد Escape به‌صورت قابل اتکا Drawer را نمی‌بندد. یک listener محدود به زمان بازبودن منو اضافه شد؛ listener هنگام بسته‌شدن cleanup می‌شود و پس از بستن، Material UI فوکوس را به دکمه بازکننده برمی‌گرداند. آیکن‌های تزئینی وضعیت نیز از درخت دسترس‌پذیری پنهان شدند.

## حفاظت داده

تست‌ها فقط با دیتابیس و media موقت و شبکه محدود به localhost اجرا می‌شوند. هیچ رمز واقعی تغییر نمی‌کند؛ دیالوگ تغییر رمز فقط باز و با Escape بسته می‌شود. production، merge، push و deploy در این فاز انجام نمی‌شوند.

## تست خودکار

از پوشه `frontend`:

```powershell
pnpm test:e2e -- --grep "landmark"
pnpm run build
```

سناریو، landmark، heading، reduced-motion، صفحه‌کلید، focus return و اندازه کنترل موبایل را بررسی می‌کند. guardهای خطای JavaScript، HTTP 5xx، شبکه خارجی و overflow همچنان فعال‌اند.

نتیجه نهایی: build تولید با `978 modules` موفق شد؛ اجرای کامل Playwright در دسکتاپ `9 passed + 1 expected skip` و در موبایل `390×844` برابر `10 passed` بود.

## تست دستی کوتاه

1. در موبایل روی دکمه منو فوکوس بگذارید و Enter بزنید؛ منو باید باز شود.
2. Escape بزنید؛ منو باید بسته و focus به همان دکمه برگردد.
3. با Tab به «تغییر رمز» بروید، Enter و سپس Escape بزنید؛ focus باید به دکمه تغییر رمز برگردد.
4. گزینه کاهش حرکت سیستم را فعال کنید؛ جابه‌جایی‌ها نباید انیمیشن طولانی داشته باشند.

# فاز ۳۳ — QA مرورگری ایزولهٔ دسکتاپ و موبایل

## محدوده تحویل

یک harness محلی Playwright برای پنل مدیریت اضافه شد تا ورود مدیر و مسیرهای اصلی، با Chrome واقعی و بدون تماس با دیتابیس توسعه یا production، تکرارپذیر بررسی شوند.

سناریوهای فعلی:

- ورود با مدیر اختصاصی تست؛
- ناوبری به «کالاها و قیمت‌ها»، «مدیریت انبار» و «مدیریت چک‌ها»؛
- اجرای همان مسیر در viewport دسکتاپ `1440×900` و موبایل `390×844`؛
- بررسی نبود overflow افقی در داشبورد و هر صفحه؛
- بازکردن dialog واقعی «ویرایش کاربر زیرمدیریت» در موبایل، اثبات حالت تمام‌صفحه `390×844` و ارتفاع لمسی حداقل ۴۴ پیکسل برای CTA.

## ایزولاسیون و حفاظت داده

- backend تست فقط وقتی بالا می‌آید که `DATABASE_URL` دقیقاً به فایل `store-e2e.db` در runtime اختصاصی زیر temp سیستم‌عامل اشاره کند؛ در غیر این صورت fail-fast می‌شود.
- در هر اجرا migrationها از صفر روی همان فایل موقت اجرا و داده نمایشی seed می‌شوند.
- کاربر و رمز تست با متغیرهای اختصاصی همان process ساخته می‌شوند و به `.env` یا داده واقعی وابسته نیستند.
- media نیز زیر همان runtime خارج از workspace قرار دارد.
- هر درخواست مرورگر به میزبانی غیر از `127.0.0.1` تست را fail می‌کند تا تماس ناخواسته با production یا سرویس بیرونی پنهان نماند.
- فقط portهای محلی `5193` و `8013` مجازند؛ خطای JavaScript، پیام `console.error` یا پاسخ HTTP 5xx نیز تست را fail می‌کند.
- runner پیش و پس از اجرا فقط مسیر temp دارای نام و hash اعتبارسنجی‌شده را پاک می‌کند؛ حتی خروج ناموفق Playwright نیز cleanup را اجرا می‌کند.
- `backend/store.db`، دیتابیس PythonAnywhere و API production در این مسیر استفاده نمی‌شوند.

## اجرا

پیش‌نیاز محلی: Python با dependencyهای backend، pnpm و Google Chrome نصب‌شده. سپس:

```powershell
cd frontend
pnpm install
pnpm test:e2e
```

برای اجرای جداگانه:

```powershell
pnpm test:e2e --project=desktop-chrome
pnpm test:e2e --project=mobile-chrome-390x844
```

در شکست، screenshot، trace و گزارش HTML زیر مسیرهای ignoreشدهٔ `test-results` و `playwright-report` باقی می‌مانند. دیتابیس موقت مستقل از این artifactها پاک می‌شود.

## نتیجه اعتبارسنجی این فاز

- Playwright `1.55.0` با Chrome نصب‌شدهٔ سیستم اجرا شد؛ دانلود browser جداگانه لازم نبود.
- نتیجه اجرای کامل: `3 passed` و `1 skipped`؛ skip مربوط به سناریوی ذاتاً موبایلی در پروژه دسکتاپ است.
- تست‌های اعداد ۴ و نقش‌ها ۱۷ موفق و build با ۹۷۸ ماژول کامل شد؛ build هنوز هشدار chunk اصلی `502.81 kB` دارد و بهینه‌سازی آن جداگانه باقی است.
- هر دو web server پس از اجرا متوقف و runtime اختصاصی temp پاک شد.
- هشدار سازگاری قدیمی `passlib` با metadata نسخه جدید `bcrypt` در stderr دیده می‌شود، اما hash و ورود موفق‌اند؛ این هشدار مانع تست نیست و تغییری در dependencyهای backend این فاز داده نشد.

## محدوده‌ای که هنوز پوشش داده نشده

این برش smoke پایه است و به‌معنای QA کامل همه نقش‌ها و همه فرم‌های مالی نیست. سناریوهای CRUD، خطا/empty/loading، تعامل‌های عددی و نقش‌های زیرمدیریت باید به‌تدریج به همین harness افزوده شوند. هیچ deploy، migration یا seed روی production انجام نشده است.

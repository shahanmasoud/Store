# فاز ۳۷ — چرخه E2E کالا، خرید، انبار، تصویر و فروشگاه

## محدوده تحویل

یک سناریوی یکپارچه به harness مرورگری افزوده شد که در هر دو viewport دسکتاپ `1440×900` و موبایل `390×844` این مسیر واقعی را طی می‌کند:

1. ساخت دسته و کنترل validation دکمه ثبت؛
2. ساخت واحد، کالای پایه و توضیح آن؛
3. انتخاب و آپلود یک PNG معتبر و مشاهده پیش‌نمایش؛
4. ساخت گونه با قیمت خرده و کنترل جداکننده سه‌رقمی فارسی؛
5. ثبت خرید سه‌واحدی با قیمت خرید و پرداخت کامل؛
6. کنترل مانده، میانگین بهای خرید و گردش «ورود خرید» در انبار؛
7. بازکردن فروشگاه عمومی و اثبات دریافت همان گونه، توضیح، قیمت، موجودی و فایل تصویر از دیتابیس و media.

حالت loading کاتالوگ فروشگاه با تأخیر کنترل‌شده پاسخ localhost مشاهده می‌شود. نبود overflow افقی در پنل، انبار، کارت فروشگاه و viewport کلی نیز کنترل می‌شود. guard عمومی تست همچنان هر `pageerror`، `console.error` و پاسخ HTTP 5xx را شکست می‌دهد.

## ایزولاسیون و حفاظت داده

- دیتابیس برای هر viewport از صفر و فقط زیر runtime hashدار temp ساخته می‌شود.
- PNG کوچک آزمون از buffer درون تست فرستاده می‌شود و backend آن را فقط در media موقت sanitize و ذخیره می‌کند.
- درخواست‌های مرورگر فقط به `127.0.0.1:5193` و `127.0.0.1:8013` مجازند.
- runner پیش و پس از اجرا runtime شامل SQLite و تصویر را حذف می‌کند.
- هیچ رکورد، تصویر، رمز یا schema در production یا `backend/store.db` تغییر نمی‌کند.

## شواهد خودکار

- اجرای هدفمند desktop: `1 passed`؛
- اجرای هدفمند mobile `390×844`: `1 passed`؛
- اجرای کامل harness پس از افزودن سناریو: desktop برابر `6 passed + 1 expected skip` و mobile برابر `7 passed`؛
- تست‌های واحد اعداد `4 passed`، نقش‌ها `17 passed` و build تولید با `978` ماژول موفق؛
- تصویر نهایی از endpoint واقعی `/media/products/...png` بارگذاری و کامل‌شدن آن در مرورگر بررسی شد؛
- قیمت خرده `۲۵۰٬۰۰۰ تومان`، قیمت خرید میانگین `۱۲۰٬۰۰۰ تومان` و مانده `۳` از UI نهایی اثبات شدند؛
- هیچ تماس شبکه خارجی، خطای JavaScript، پاسخ 5xx یا overflow افقی ثبت نشد.

فرمان هدفمند از پوشه `frontend`:

```powershell
pnpm test:e2e -- --grep "چرخه کامل کالا"
```

## تست دستی کوتاه

1. در «کالاها»، یک دسته، واحد، کالا و گونه با قیمت خرده بسازید و برای کالا تصویر PNG/JPEG/WebP انتخاب کنید.
2. در دسکتاپ و سپس موبایل، پیش‌نمایش تصویر، پیام‌های روشن validation و نبود بریدگی یا اسکرول افقی را بررسی کنید.
3. در «خرید»، همان گونه را با تعداد و قیمت خرید ثبت و سپس «نمایش انبار» را بزنید؛ مانده، میانگین بها و گردش ورود خرید باید درست باشند.
4. «مشاهده فروشگاه» را بزنید؛ همان نام، توضیح، قیمت خرده، موجودی و تصویر باید روی کارت عمومی دیده شود.

این فاز merge، push، deploy یا تماس با production ندارد.

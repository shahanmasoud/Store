# فاز ۲۲ — دسترسی امن چک‌ها و گزارش‌ها

مدیر اصلی اکنون می‌تواند مجوز مستقل `can_cheques_reports` را هنگام ساخت یا ویرایش زیرمدیر فعال کند. این نقش به ثبت، ویرایش، وصول و برگشت چک، تاریخچه ممیزی و گزارش‌های مدیریتی دسترسی دارد. ابطال چک همچنان فقط در اختیار مدیر اصلی است.

کنترل‌های امنیتی این برش:

- فرم چک از endpoint حداقلی اشخاص فقط شامل شناسه، نام و نوع شخص استفاده می‌کند.
- پاسخ سررسیدها بر اساس نقش فیلتر می‌شود؛ نقش دفتر جزئیات چک و نقش چک جزئیات اسناد دفتر را دریافت نمی‌کند.
- عملیات چک auditدار است و لغو مجوز نشست قبلی را فوراً باطل می‌کند.
- گزارش موجودی برای مسئول کالا/انبار خواندنی باقی مانده است.

نتیجه تست: کل backend برابر `201 passed`، تست متمرکز برابر `47 passed` و build تولید frontend با `976 modules transformed` موفق بود. migration جدید لازم نبود.

## تست دستی دسکتاپ

1. زیرمدیری فقط با مجوز «چک‌ها و گزارش‌ها» بسازید؛ منو باید خانه، چک‌ها و گزارش‌ها را نشان دهد.
2. چک بسازید، ویرایش کنید، وصول/برگشت و تاریخچه را بررسی کنید.
3. ابطال را امتحان کنید؛ باید فقط برای مدیر اصلی مجاز باشد.
4. گزارش‌ها را با بازه معتبر/نامعتبر و حالت خطا و retry بررسی کنید.
5. مجوز را خاموش کنید؛ نشست قبلی باید پایان یابد.

## تست دستی موبایل `390 × 844`

Drawer، کارت‌های نقش، فرم‌ها و dialogهای چک را با صفحه‌کلید باز بررسی کنید. CTAها باید قابل دسترس، اهداف لمس حداقل ۴۴ پیکسل و صفحات بدون هم‌پوشانی یا اسکرول افقی باشند. حالت‌های loading، empty و error نیز بررسی شوند.

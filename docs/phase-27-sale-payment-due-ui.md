# فاز ۲۷ — رابط سررسید پرداخت نسیه فروش

## محدوده تحویل

- بخش «فاکتورهای اخیر» در همان صفحه فروش با حالت‌های loading، empty، error و retry
- کارت بازشونده فاکتور و نمایش پرداخت‌ها با اعداد فارسی
- نمایش اکشن ویرایش فقط برای پرداخت `pending` فاکتور فعال
- دیالوگ ویرایش سررسید با تاریخ جلالی nullable، دلیل اجباری و جلوگیری از ثبت بدون تغییر
- نمایش تاریخچه audit با loading، empty، error و retry مستقل
- مدیریت تعارض ۴۰۹ و دریافت نسخه تازه بدون reset کردن فرم ثبت فروش

## تجربه موبایل

- دیالوگ زیر breakpoint موبایل تمام‌صفحه است.
- کارت‌ها تک‌ستونه، متن‌ها overflow-safe و دکمه‌ها حداقل ۴۴ پیکسل هستند.
- نوار عملیات پایین دیالوگ sticky است و safe-area پایین صفحه را رعایت می‌کند.

## تست خودکار

- `pnpm test:numbers`: چهار تست موفق
- `pnpm test:roles`: هفده تست موفق
- `pnpm build`: موفق با ۹۷۸ ماژول؛ فقط هشدار شناخته‌شده chunk بزرگ باقی است.
- `git diff --check`: بدون خطا، به‌جز هشدار line-ending ویندوز

## QA واقعی Chrome

- برنامه با دیتابیس QA جداگانه و migration 0018 روی پورت‌های محلی اجرا شد؛ production و `backend/store.db` در این مرحله لمس نشدند.
- داشبورد در Chrome دسکتاپ و viewport واقعی `390 × 844` render شد؛ در نمای موبایل هم‌پوشانی و overflow افقی دیده نشد.
- افزونه کنترل Chrome پس از ورود، clickهای React روی منوی فروش و حتی منوی موبایل را اعمال نکرد. بنابراین تعامل صفحه فروش، دیالوگ، keyboard و stale flow هنوز تأیید دستی نشده است.

## تست دستی بعدی

در Chrome وارد «فروش» شوید، یک فاکتور دارای پرداخت pending را باز کنید و سررسید را اضافه، تغییر و حذف کنید. پس از هر ذخیره refresh کنید و تاریخچه را ببینید. سپس در `390 × 844` بازبودن صفحه‌کلید، sticky بودن دکمه‌ها، نبود overflow و در دسترس‌بودن CTAها را کنترل کنید. پرداخت received و فاکتور لغوشده نباید اکشن ویرایش داشته باشند.

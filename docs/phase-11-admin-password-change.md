# فاز ۱۱: تغییر رمز حساب مدیریت

## محدوده

این تحویل فقط امکان تغییر رمز **کاربر مدیریتی واردشده** را اضافه می‌کند. تعریف کاربر زیرمدیریت، نقش‌ها و مدیریت کاربران در تحویل بعدی انجام می‌شود.

## قرارداد API

```text
POST /api/v1/auth/change-password
Authorization: Bearer <admin-token>
```

```json
{
  "current_password": "old-password",
  "new_password": "new-password",
  "confirm_password": "new-password"
}
```

قواعد اعتبارسنجی:

- رمز فعلی باید درست باشد.
- رمز جدید حداقل ۸ و حداکثر ۱۲۸ کاراکتر است.
- رمز جدید باید با رمز فعلی متفاوت باشد.
- تکرار رمز باید دقیقاً با رمز جدید یکسان باشد.

## امنیت نشست

فیلد `token_version` با migration شماره `0009` به کاربران موجود اضافه می‌شود و مقدار اولیه آن صفر است. نسخه در JWT مدیریتی ثبت و در هر درخواست کنترل می‌شود. پس از تغییر موفق رمز، نسخه افزایش پیدا می‌کند و تمام توکن‌های قبلی آن کاربر بلافاصله نامعتبر می‌شوند.

## تجربه کاربری

- گزینه «تغییر رمز» در هدر پنل مدیریت قرار دارد.
- فرم در Dialog فارسی و RTL نمایش داده می‌شود و در موبایل عرض صفحه را رعایت می‌کند.
- فرم حالت‌های validation، loading، error و success دارد.
- هر سه فیلد رمز کنترل مستقل نمایش/پنهان‌سازی با هدف لمسی مناسب موبایل دارند.
- پس از موفقیت، پیام تأیید کوتاه نمایش داده می‌شود و خروج اجباری انجام می‌گیرد.

## تست دستی

1. با حساب مدیر وارد پنل شوید و از هدر «تغییر رمز» را بزنید.
2. رمز کمتر از ۸ کاراکتر، تکرار ناهماهنگ و رمز برابر با رمز فعلی را جداگانه امتحان کنید؛ ثبت نباید انجام شود.
3. رمز فعلی اشتباه وارد کنید؛ باید پیام فارسی خطا ببینید و همچنان وارد بمانید.
4. رمز صحیح و یک رمز جدید معتبر وارد کنید؛ پیام موفقیت باید ظاهر و سپس صفحه ورود نمایش داده شود.
5. ورود با رمز قبلی باید رد و ورود با رمز جدید باید موفق شود.
6. مراحل ۱ تا ۵ را در عرض موبایل نیز تکرار کنید؛ Dialog نباید بیرون‌زدگی افقی یا هم‌پوشانی دکمه‌ها داشته باشد.

## تست خودکار

تست‌های `backend/tests/test_auth.py` تغییر موفق رمز، رد رمز فعلی اشتباه، policy رمز، نیاز به احراز هویت و ابطال توکن قبلی را پوشش می‌دهند.

# فاز ۳۶ — ماتریس E2E نقش‌های پنل مدیریت

## محدوده تحویل

ماتریس واقعی پنج نقش با Chrome و دیتابیس موقت به harness مرورگری اضافه شد:

- زیرمدیر فروش: خانه، یادآوری‌ها و فروش؛
- زیرمدیر کالا و انبار: خانه، کالاها، خرید و انبار؛
- زیرمدیر دفتر حساب: خانه، یادآوری‌ها و دفتر حساب؛
- زیرمدیر چک و گزارش: خانه، یادآوری‌ها، چک‌ها و گزارش‌ها؛
- مدیر اصلی: همه بخش‌ها، اتصال آنلاین و کاربران و دسترسی‌ها.

برای هر حساب، تست علاوه بر ورود موفق، حضور تک‌تک منوهای مجاز و نبودن تک‌تک منوهای غیرمجاز را کنترل می‌کند، یکی از صفحات عملیاتی نقش را باز می‌کند و نبود overflow افقی را می‌سنجد. همین سناریو بدون تغییر منطق در viewport دسکتاپ `1440×900` و موبایل `390×844` اجرا می‌شود.

در جریان تست زیرمدیرها یک اخطار دسترس‌پذیری React کشف شد: دکمه نمایشی «ورود به بخش» داخل `CardActionArea` دکمه‌ای قرار گرفته بود و HTML شامل دکمه تو‌در‌تو می‌شد. عنصر داخلی به نشان بصری غیرتعاملی تبدیل شد؛ کل کارت همچنان یک هدف لمسی واحد با ارتفاع مناسب است.

## ایزولاسیون و حفاظت داده

- چهار حساب تک‌مجوز فقط در `backend/tests/e2e/start_backend.py` و پس از اعتبارسنجی مسیر temp ساخته می‌شوند.
- `DATABASE_URL` فقط فایل `store-e2e.db` داخل runtime hashدار temp را می‌پذیرد و media نیز همان‌جا قرار می‌گیرد.
- guard مرورگر هر درخواست خارج از `127.0.0.1:5193` و `127.0.0.1:8013` را رد می‌کند.
- runner پیش و پس از هر viewport دیتابیس را حذف و از صفر migrate/seed می‌کند؛ هیچ حساب، رمز یا رکورد production تغییر نمی‌کند.

## شواهد خودکار

- اجرای هدفمند desktop: یک تست موفق؛ پنج نقش در `1440×900`.
- اجرای هدفمند mobile: یک تست موفق؛ پنج نقش در `390×844`.
- هیچ `pageerror`، `console.error`، پاسخ HTTP 5xx، تماس شبکه خارجی یا overflow افقی ثبت نشد.
- هشدار قدیمی سازگاری metadata میان `passlib` و نسخه نصب‌شده `bcrypt` در stderr وجود دارد، اما hash و هر پنج ورود موفق‌اند و این هشدار شکست آزمون نیست.

فرمان از پوشه `frontend`:

```powershell
pnpm test:e2e -- --grep "ماتریس پنج نقش"
```

## تست دستی کوتاه

1. برای هر زیرمدیر وارد شوید و نام کامل او را در بالای صفحه بررسی کنید.
2. در دسکتاپ منوی ثابت و در موبایل Drawer را باز کنید؛ فقط بخش‌های فهرست‌شده برای همان نقش باید دیده شوند.
3. هر منوی مجاز را یک بار باز کنید و نبود صفحه خالی، خطای دسترسی، بریدگی یا اسکرول افقی را بررسی کنید.
4. با مدیر اصلی ورود کنید و وجود «اتصال آنلاین» و «کاربران و دسترسی‌ها» را، که برای زیرمدیرها پنهان‌اند، تأیید کنید.

این فاز merge، push، deploy یا تماس با production ندارد.

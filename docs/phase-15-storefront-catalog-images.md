# فاز ۱۵ ـ کاتالوگ فروشگاه و تصویر کالا

## هدف و محدوده

این مرحله، ویترین فروشگاه را مستقیماً به اطلاعات معتبر دیتابیس متصل می‌کند و امکان ثبت یک تصویر اصلی برای هر کالا را در اختیار مدیر اصلی می‌گذارد. فایل دیتابیس و تصاویر عملیاتی داخل Git نگهداری نمی‌شوند.

## قرارداد API

### کاتالوگ عمومی

`GET /api/v1/storefront/catalog` بدون توکن قابل خواندن است. هر سطر نماینده یک گونه کالا است:

```json
{
  "variant_id": 12,
  "variant_name": "عدس کیلویی",
  "sku": "LENTIL-1",
  "product_id": 4,
  "product_name": "عدس",
  "description": "عدس تازه",
  "category_id": 2,
  "category_name": "حبوبات",
  "unit_id": 1,
  "unit_name": "کیلوگرم",
  "unit_symbol": "kg",
  "retail_price_rial": 1250000,
  "available_quantity": "12.500",
  "image_url": "/media/products/8f...c1.webp"
}
```

- فقط گونه، کالا و واحد فعال منتشر می‌شوند.
- کالای بدون دسته نیز منتشر می‌شود. اگر یک رکورد قدیمی به دسته غیرفعال اشاره کند، کالا حذف نمی‌شود و اطلاعات دسته `null` است.
- موجودی قابل فروش برابر موجودی انبار منهای مجموع رزروهای فعال با وضعیت `reserved` و منقضی‌نشده در تاریخ امروز تهران است و هرگز کمتر از صفر برگردانده نمی‌شود.
- محاسبه رزروها با زیرپرس‌وجوی تجمیعی انجام می‌شود و N+1 ندارد.

### تصویر کالا

- `PUT /api/v1/products/{product_id}/image`
- احراز هویت: فقط مدیر اصلی (`is_superuser`)
- بدنه: `multipart/form-data` با فیلد اجباری `image`
- فرمت: JPEG، PNG یا WebP؛ هم MIME اعلام‌شده و هم محتوای واقعی بررسی می‌شوند.
- سقف پیش‌فرض: ۵ مگابایت؛ تصویر decode و دوباره encode می‌شود تا metadata و محتوای اضافه حذف شود.
- پاسخ: `{"product_id": 4, "image_url": "/media/products/<random>.jpg"}`

جایگزینی، فایل تازه را با نام تصادفی ذخیره و تنها پس از ثبت موفق دیتابیس، فایل قبلی را کنار می‌گذارد. نام ارسالی کاربر هیچ‌گاه در مسیر ذخیره‌سازی استفاده نمی‌شود.

- `DELETE /api/v1/products/{product_id}/image`
- احراز هویت: فقط مدیر اصلی
- پاسخ: `{"product_id": 4, "image_url": null}`

حذف ابتدا فایل را از مسیر عمومی قرنطینه می‌کند؛ اگر ثبت دیتابیس شکست بخورد، برای بازگردانی فایل تلاش می‌شود.

## تنظیم PythonAnywhere

در فایل خصوصی محیط، مسیری خارج از checkout انتخاب شود تا deploy تصاویر را حذف نکند:

```env
MEDIA_ROOT=/home/Hobubat/store-data/media
MEDIA_URL_PREFIX=/media
PRODUCT_IMAGE_MAX_BYTES=5242880
```

دایرکتوری در شروع برنامه ساخته و از `/media` سرو می‌شود. این پوشه باید همراه دیتابیس در بکاپ زمان‌بندی‌شده قرار بگیرد. پس از pull، وابستگی‌های تازه `Pillow` و `python-multipart` نصب و migration زیر اجرا شود:

```powershell
alembic upgrade head
```

مهاجرت `0013_product_image` فقط ستون nullable به `products` اضافه می‌کند و هیچ داده‌ای را بازنویسی نمی‌کند.

## نتیجه آزمون توسعه

- تست backend: هر ۱۷۷ آزمون موفق، شامل PNG/JPEG/WebP واقعی، فایل جعلی، سقف حجم، مجوز مدیر اصلی، رزرو و موجودی قابل فروش.
- build frontend: موفق با ۹۷۶ ماژول؛ تست helperهای عددی فارسی ۳ از ۳ موفق.
- migration روی کپی دیتابیس موجود: integrity برابر `ok`، revision برابر `0013_product_image` و همه ۴ کالای قبلی حفظ شدند.
- QA دسکتاپ: سه گونه واقعی دیتابیس در فروشگاه دیده شدند و افزودن به سبد با `variant_id` واقعی کار کرد.
- QA موبایل در `390 × 844`: عرض محتوا از viewport بیشتر نشد، کارت‌ها هم‌پوشانی نداشتند و دکمه‌های اصلی حداقل ۴۴ پیکسل بودند؛ دیالوگ تصویر کالا نیز تمام‌صفحه و قابل لمس بود.

این نتایج مربوط به محیط توسعه‌اند. استقرار PythonAnywhere و تست پذیرش مالک فروشگاه هنوز انجام نشده است.

## تست دستی کوتاه

1. بدون ورود، صفحه فروشگاه را باز کنید و نام، قیمت، موجودی و تصویر کالا را با پنل مدیریت مقایسه کنید.
2. یک رزرو فعال بسازید؛ موجودی قابل فروش باید به همان اندازه کم شود. رزرو آزادشده یا منقضی نباید کم شود.
3. با مدیر اصلی، PNG/JPEG/WebP کمتر از ۵ مگابایت بارگذاری و سپس جایگزین کنید؛ تصویر جدید باید در فروشگاه دیده شود.
4. تصویر را حذف کنید؛ فروشگاه باید placeholder نشان دهد.
5. با کاربر زیرمدیریت، بارگذاری یا حذف باید با پیام عدم دسترسی رد شود.
6. فایل متنی با پسوند JPG و فایل بزرگ‌تر از سقف را امتحان کنید؛ باید بدون تغییر تصویر فعلی رد شوند.
7. مراحل ۱ تا ۴ را در عرض موبایل ۳۹۰ پیکسل نیز اجرا کنید و نبود اسکرول افقی، هم‌پوشانی و هدف لمسی کوچک را بررسی کنید.
